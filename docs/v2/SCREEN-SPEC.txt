SUMMARY: Four coach-facing surfaces plus one shared feedback layer, all inside the single 390px artboard, switched by opacity/visibility flags (full screens) or translateY(105%) (bottom sheets).

THE SHAPE OF THE COACH SIDE: it is a two-stroke engine. The Session Tagger (tgS) is intake — one clip bound to athlete × movement-stage × voice note, filed straight into an open chapter draft from the beach. The Composer (composerS) is output — that draft turned into student-readable prose and published. The Coach Desk (coachS) is the debt dashboard between them (2 drafts, 2 inbox, 128 clips, 71% habits, 6/11 path steps), and the Athlete Sheet (athS) is the 5-second briefing before speaking to a person. Role switching is a single pill in the same position on both sides: "Coach ▾" → student library, "Student ▾" → coach desk.

══ HOW THE READING MODEL ACTUALLY WORKS ══
  • {{onRdScroll}} reads e.target.scrollTop / (scrollHeight − clientHeight), clamps to [0,1], and stores it as state.pct — throttled through a single requestAnimationFrame guard (this._raf) so it fires at most once per frame.
  • Constants in the logic: total = 38 pages, mins = 16. page = Math.max(1, Math.round(pct × 38)); minutesLeft = Math.max(1, Math.ceil((1 − pct) × 16)). Both are DERIVED, not stored — so "38 pages" is a fiction the prototype asserts; a real build must compute it from rendered content height or word count.
  • The SAME pct feeds three separate bars via {{pctW}}: this footer, the library "currently reading" card, and the TOC chapter-03 mini-bar. It is the single source of "where am I".
  • {{tocPct}} renders the same number as a percentage string for the TOC.
  • Font stepping: FS = [15.5, 17, 18.5, 20.5], index clamped 0..3, default 1. {{fsUp}}/{{fsDown}} write --fs on the artboard root.
